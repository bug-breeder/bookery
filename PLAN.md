# Plan and working agreement

> This document is carried over unmodified from the reference build (see
> `README.md`). It documents the design decisions and traps encountered while
> running this pipeline end-to-end against one real book; it contains no book
> content itself, only factual references to the source's title/structure.
> Treat the specifics below (chapter counts, phase history) as a worked
> example, not as configuration for your own run.

Read this first if you are picking the project up cold. It holds the parts a
new session cannot rediscover cheaply: what we are building, the order we are
building it in, the decisions already made and why, and the traps that have
already cost time.

**Current state lives in `PROGRESS.md`, which is generated.** Never hand-edit
it and never trust a claim of progress made anywhere else, including in a
conversation summary. `PROGRESS.md` is derived from the gate reports, so it
cannot claim a chapter is done while its gates disagree.

- Intent, decisions, conventions: this file, written by hand.
- State, counts, per-chapter status: `PROGRESS.md`, generated by
  `python -m pipeline.status`.

## The goal

Convert *Networks, Crowds, and Markets* (Easley & Kleinberg, 2010 draft) from
a single 833-page PDF into a Docusaurus v3 site with **no content loss**, where
"no loss" is enforced by automated gates rather than asserted. The pipeline
must be reusable and auditable: any chapter can be re-run independently, and
every claim of correctness must trace back to a check that could have failed.

Licensing: the PDF is published freely by its authors but the book is
copyright Cambridge University Press. This build is a local validation
artifact. Do not deploy it publicly.

## How to resume work

```bash
# See where things actually stand.
python -m pipeline.status && cat PROGRESS.md

# Full pipeline for one chapter (stage 1 is the slow one, ~1 min/chapter).
python -m pipeline.stage1_extract  --chapter N
python -m pipeline.stage2_reconcile --chapter N
python -m pipeline.stage3_assets    --chapter N
python -m pipeline.stage4_emit      --chapter N   # pass every emitted chapter

# Verify. --build runs the site build gate and is required for a green result.
python -m verify.runner --chapter N --build

# Gate 8: adjudicate flagged pages.
python -m verify.visual --chapter N --render        # proof sheets + page images
python -m verify.visual --chapter N --order-check   # deterministic order check
python -m verify.visual --chapter N --auto-record   # verdicts for exact matches

pytest -q                                          # regression suite
```

`stage4_emit` must be given **every** chapter that should exist in the site,
not just the new one, because it regenerates `sidebars.ts`, the home page and
the cross-reference registry from the full emitted set.

## Architecture

Six stages, each writing a checkpoint so work is resumable and inspectable:

| Stage | Module | Output |
| --- | --- | --- |
| 0 | `pipeline/stage0_acquire.py` | `work/triage.json` — chapter/part boundary map |
| 1 | `pipeline/stage1_extract.py` | `work/extract/{marker,docling}/chNN.json` |
| 2 | `pipeline/stage2_reconcile.py` | `work/reconcile/chNN.json` — canonical model |
| 3 | `pipeline/stage3_assets.py` | figure crops + `work/assets.json` |
| 4 | `pipeline/stage4_emit.py` | `site/docs/**`, `sidebars.ts` |
| 5 | `verify/runner.py` | `reports/chNN.json`, `reports/review-queue.md` |

Eight gates, all of which must pass for a chapter to be green: text coverage,
numeric fidelity, structural counts, assets, math, cross-references, site
build, visual adjudication.

### The central design decision

**Text comes from the PDF text layer; structure comes from the extractors.**
Marker and Docling are run independently over the same pages and used as
structural sources *and* as validators of each other. Where they disagree, the
block is flagged for visual adjudication rather than resolved by guesswork.
Their text is never trusted over the text layer, because a model that
paraphrases is indistinguishable from a model that transcribes until you diff
it.

For a scanned PDF with no reliable text layer this inverts and model text
becomes primary. That path is not exercised by this fixture.

## Phase order, and why

Phases are ordered to find expensive surprises on one chapter rather than
twenty. Do not reorder them to get a higher chapter count sooner.

1. **Prose pilot (ch 2)** — prove the whole pipeline on an ordinary chapter.
2. **Tables (ch 6)** — payoff matrices. Done, and it was worth doing early: it
   found five defects that chapters 1 and 2 also had, including one that had
   been corrupting their text all along (the f-ligature space).
3. **Mathematics (ch 14)** — spectral content. Untested path: all three green
   chapters contain **zero display equations** in the model, so Gate 5 has so
   far passed vacuously, reporting `"equations": 0`. Chapter 6 does contain
   display math (the mixed-strategy derivations on pp. 180–182) which is
   currently emitted as paragraph text rather than recognised as equations, so
   equation *detection* is the real work here, not just KaTeX. Expect this to
   be the hardest phase; Marker runs in fast mode with no LLM, which is exactly
   where equations suffer.
4. **Front matter** — ch 1 and the Preface (PDF pp. 9-14). Done. The Preface
   is modelled as chapter 0 in the boundary map rather than a bespoke path,
   so it gets the exact same stage1-4 and gate machinery as every numbered
   chapter for free. See the trap below on why that is safe.
5. **Bulk run** — remaining chapters, batched by part.
6. **Ship** — search, `MANIFEST.json`, README, accessibility, polish.

## Conventions that must not change silently

- **Chapter bodies are `.md`, not `.mdx`.** The prose is full of bare `<`, `{`
  and `}`; each is a build error under MDX. `markdown.format: 'detect'` keeps
  them CommonMark while still running the remark math plugins.
- **Doc ids carry the chapter number** (`id: 02-graphs` in front matter).
  Docusaurus strips a leading `NN-` from filenames, which would drop the
  number from the route and break every cross-reference.
- **Routes/anchors**: `/{part-slug}/{NN-title}` with `#sec-N-M`, `#fig-N-M`,
  `#tbl-N-M`, and `#ref-N` in the bibliography.
- **`sidebars.ts`, `docs/index.md` and the bibliography are generated.** Never
  hand-edit; regenerate with `stage4_emit`.
- **`onBrokenLinks`, `onBrokenAnchors`, `onBrokenMarkdownLinks` are all
  `throw`.** A broken link is a lost cross-reference. Gate 7 requires zero
  warnings too, so fix deprecation warnings rather than tolerating them.
- **webpack is pinned to 5.101.3** via `overrides` in `site/package.json`.
  Newer webpack rejects the options Docusaurus 3.9.2's `webpackbar` passes to
  `ProgressPlugin`, and the build dies before compiling.
- **Deferred cross-references.** A reference whose target chapter is not yet
  emitted is left as plain text and recorded as `deferred`, not failed —
  linking it would make an incremental build unbuildable. Once every chapter
  is emitted the deferred list must be empty; check this in phase 6.

## Traps already paid for

Each of these was a real defect. Every one has a regression test; if you
"simplify" the code and a test in `tests/test_artifacts.py` fails, the defect
is back. Several were invisible to the coverage and numeric gates because
**both sides of the comparison were wrong in the same way** — that is the
failure mode to fear most.

- **Captions run to several lines** and only the first carries the
  `Figure N.N:` label. Caption extent comes from the extractors' caption
  bboxes. Without it the remainder is emitted as loose body prose.
- **Figure bboxes must be clipped above their caption.** Extractor picture
  regions sometimes swallow the caption, which then counts as figure interior
  and is dropped from the emitted page *and* the reference. No gate can see
  this. Sub-captions inside the drawing are deliberately left in place;
  clipping to them would cut multi-panel figures apart.
- **Brackets in alt text silently kill images.** Captions carry citations like
  `[214]`; carried into alt text the `[` ends the Markdown image early and the
  figure renders as literal prose while the PNG sits happily on disk. Gate 4
  now checks figures reach the built HTML as real `<img>` elements.
- **Small caps must be restyled, not rewritten.** `MIT` is set in `CMCSC10`
  and extracts as `mit`. Uppercasing it would put characters in the output the
  source does not contain and break coverage; it is wrapped in
  `<span class="node">` instead. Detection is by font, not by a name list.
- **`(a) ...` is ambiguous**: a figure sub-caption (set ~10pt) or an exercise
  sub-part (body size 12pt). Size disambiguates them.
- **Never indent emitted text with four spaces.** Exercise sub-parts indented
  that way became code blocks. Use `<span class="exercise-part">`, which also
  keeps inner Markdown links working — a raw HTML *block* would not.
- **Furniture is detected by positional slot occupancy**, not text recurrence;
  section-specific running heads recur too rarely to threshold on.
- **The footnote counter must require both small size and page-bottom
  position.** Size alone counted 16 karate-club node labels as footnotes.
- **Dehyphenation must use the same attested-forms set on both sides.**
  Whether `social-networking` keeps its hyphen depends on the form appearing
  elsewhere, so a per-page check must be given the whole chapter's set.
- **Ligatures** (`ﬁ`, `ﬀ`) are expanded on output or search breaks.
- **A space after an f-ligature is not a character.** TeX encodes it as pure
  positioning, so the text layer reads `payoffmatrix`, `payoffof`,
  `trade-offbetween` where the page plainly reads two words. 163 words were
  fused across chapters 1, 2 and 6. Because the reference is built from the
  same text layer, *every gate agreed with itself and passed*; it was found by
  reading the rendered page. Lines are therefore assembled character by
  character from `rawdict`, inserting a space wherever the glyph gap exceeds
  `SPACE_GAP_RATIO`. That ratio has a floor as well as a ceiling: at 0.2 it
  closed `1 − q` into `1 −q`. Keep it at 0.15.
- **Section headings wrap.** Section 6.8's title runs to two lines and the
  break falls inside `Anal-/ysis`. Emitting only the first line orphaned the
  remainder as body prose and split the word. Headings accumulate like
  captions, and the label is parsed from the joined text.
- **Payoff matrices are not tables in the file.** TeX draws them with `\put`
  rules, so neither extractor reports a table or a picture; they are recovered
  from geometry in `pipeline/matrix.py`. A cell is a comma-separated tuple of
  numbers in the math italic face; strategy names are the text-italic runs
  beside and above them. Every part of the payoff pattern is load-bearing:
  `.48, .12` (no leading zero), `+1, −1` (explicit plus), `4, 4, 4` (three
  players). A 1×1 grid is real — iterated deletion leaves one outcome in
  Figure 6.22 — and is accepted only when a caption sits directly below it.
- **A matrix is a figure, not a table.** The book captions all 28 of chapter
  6's exhibits "Figure N.N" and the prose says "see Figure 6.1", so matrices
  keep the `fig-` anchor and count as figures. They are emitted as Markdown
  tables and have no asset, so the asset gate must be told which labels are
  realised as tables instead of images.
- **Bare decimals and ordinals must be countable.** `numbers()` required a
  leading digit, so `.48` and `.42` were invisible to the numeric gate on both
  sides; and digits followed by letters were excluded, so `501st` was too.
- **The cross-extractor numeric check is chapter-wide and one-directional.**
  Per page it flagged every paragraph straddling a page break, because the
  extractors attribute the whole paragraph to one page. And only "the extractor
  saw a number we do not have" is evidence of anything: the reverse just means
  Docling dropped an equation or a list marker, which it does constantly.
- **Count extractor items, not regions.** Docling emits one provenance box per
  page for a paragraph that spans a break, each carrying the item's whole text,
  and Marker nests list items inside a group whose html repeats them. Counting
  regions inflated the extractor's side and invented disagreements.
- **The Preface is chapter 0, injected after the offset invariant is
  checked, not before.** It is front matter paginated in lowercase roman
  numerals (i-vi), a different sequence from the arabic body pagination
  every numbered chapter's `printed_page` is checked against in
  `stage0_acquire.py`. Adding it to the TOC-parsed chapter list before that
  invariant runs would break the "every chapter shares one offset" check
  that catches a real boundary-detection bug; it is appended afterwards
  instead, with its own `printed_page` counted 1-based in its own roman
  sequence. Everything that reads `printed_to_pdf_offset`/`printed_page`
  turned out to be cosmetic display, never a correctness check (confirmed by
  grepping every call site before relying on this) — `pipeline.config.
  printed_page_range()` renders it back to roman numerals for humans.
- **A gate must not confuse "ran and found zero" with "did not run".** Gate
  4 (assets) used to `BLOCKED` unconditionally on an empty assets list,
  which made a figure-free chapter — the Preface has none — permanently
  unable to reach PASS, the same trap gate 5 (math) already avoided for a
  chapter with zero equations. Fixed by having the caller check the
  `assets.json` *key*, not the list's truthiness, and letting the gate's
  existing `referenced_but_absent` check catch a chapter that should have
  figures but does not.
- **The order check excludes matrices.** A table has no single reading order:
  the PDF prints the column player above its strategies while the emitted
  Markdown linearises the grid row by row. Comparing them reported a difference
  on every matrix page. Matrix content is checked instead by the payoff-cell
  multiset and by `check_payoff_placement`, which re-reads the PDF geometry and
  requires each cell to sit on its row-header's baseline and in its
  column-header's column — the only check that can catch a transposition.

## Verification philosophy

- A gate that has never failed has not been tested. When a gate passes on a
  chapter that lacks the relevant content, say so rather than counting it.
- Prefer a deterministic check to an eyeball. Gate 8 compares the emitted
  token *sequence* per page against the page's text layer, which catches
  reordering and duplication that the chapter-level multiset coverage gate
  tolerates. Visual review is then spent on figures, where automation is weak.
- Verdicts are durable records under `work/proofs/chNN/verdict-<page>.json`
  and name their reviewer (`agent` vs `automated-order-check`) and what was
  checked. Do not record a verdict for something you did not actually inspect.
- Fixing the pipeline is not enough; fix the *gate* that failed to catch it.
  Three of the defects above were found by a browser or by eye, which means
  the harness had a hole.
